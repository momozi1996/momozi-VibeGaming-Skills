# 从完整参考提炼构建方法

## 不是让模型一次写一整款游戏

可靠路线是「读参考 → 可玩骨架 → 分模块工艺 → 单一状态集成 → 截图修正」。variant 继承已工作的工程，按阶段替换；rebuild 逐阶段补齐。初次先用默认内容让主循环成立，再换题材，不同时重写引擎、玩法和美术。

| 阶段 | 输入／实现 | 必须拿到的证据 |
|---|---|---|
| 0 工程合同 | 原 package/lock；读 architecture/contracts；确定世界单位、输入、状态、对象生命周期 | `index.html`含game-canvas/ui-root/boot，主循环可见，错误显示不是白屏 |
| 1 可驾驶灰盒（仅中间阶段） | track.sample/nearest/mapPoints + simulation.reset/start/update；按 world-spec 建闭环曲线 | 车能手动加减速／转向；方向正确；离路减速；不能跨检查点刷圈 |
| 2 场景工艺 | 把海岸半径／地面色带／道路ribbon／海面shader／植物合批分开；按新主题造地标 | 起点、连续道路、岸线无穿透；弯道可读；高低画质都可看见路 |
| 3 角色与车 | 按racer-spec：头身比例、圆润车壳、轮胎、四肢、耳尾与饰品；createKart实现动画与dispose | 独立展示正／侧／背，6角色可区分；创建两辆同角色不串轮胎／转向动画 |
| 4 比赛闭环 | simulation拥有检查点、漂移、道具、拾取重生、AI／碰撞、圈数、成绩；scene只读state | 16项基线模拟测试；完整完赛；暂停不累积道具时间 |
| 5 镜头与界面 | main组装角色／场景／输入／相机；UI呈现状态；触控输入要处理cancel/blur | 菜单主角正面3/4、右侧大主视觉，比赛背面贴近；390×844无重要遮挡 |
| 6 视听与交付 | 基于世界坐标触发粒子；用户手势开启WebAudio；真实PNG；生产构建 | console/network无未解释错误，导出PNG，完赛＋重开，生产预览截图 |

灰盒仅用于第一轮行为验收，最后不得替代完整角色和场景。详细网格／shader写法读当前模块源文件，不要把程序化几何描述成不存在的GLB素材。

## 视觉迭代顺序

截图在同一状态、尺寸、DPR、镜头与质量档下采集。先修构图／主角尺寸／镜头 → 道路及地标大轮廓 → 角色比例 → 色彩材质 → UI和粒子。每轮记录「观察、原因假设、改的文件、重拍证据」。如果看不到图像，不能仅凭截图文件已生成声称画面符合。

性能看真实场景统计和真实帧率：叶片按材质合批、路肩实例化、粒子池化；降低DPR／阴影等级要作为画质策略披露。不要为截图关闭正常流程的功能。

## 续跑文件

在输出 `PROGRESS.md` 保留：模式、主题合同、输出路径、入口和端口、已完成阶段、失败测试/截图路径、下一步具体修改、已知差异。上下文中断后先读它与失败模块；不要重建相同输出或重新复制基线抹掉修改。最终报告区分复制继承、模型新写、运行验证、人工观察。
