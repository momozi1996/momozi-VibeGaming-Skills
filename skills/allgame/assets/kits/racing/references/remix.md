# 换风格、场景、角色：从基线到新游戏

## 定义新设计，不把所有东西都冻结

先在输出写 `DESIGN-BRIEF.md`：主题一句话、5个颜色、主角造型语汇、道路材料、3个远/中/近地标、主循环、目标设备、必须保留与有意改变的行为。合理缺省沿用玩法，不擅自扩为开放世界／多人。

`project.py create --mode variant --preset sakura|sunset`：完整源码＋本地字体＋真实游戏；新增 `src/theme.js` 连接天空、雾、灯、地面、道路、植被、seed与trackPoints，并改菜单配色和标题。**这两个预设是樱色／夕阳海岸换肤，不是樱花树造型／全新关卡已自动完成。** 颜色修改不得用CSS filter把整个画面统一染色来替代材质工作。

## 修改入口和连带影响

| 用户想改 | 实际入口 | 必须同步／验证 |
|---|---|---|
| 配色／昼夜 | theme.colors、main.js照明/天空/bloom、ui.css | 海面shader内部颜色仍在track.js；只改天空不会自动改海；夜景仍保证路缘/道具可辨 |
| 改赛道弯形 | variant theme.trackPoints（XZ），exact衍生的track.js points | sample/nearest/map由同curve导出；检查闭环、自交、急弯、道路与海岸重合；3圈全程AI，不只起点截图 |
| 改地貌／场景 | track.js的地面、coastBins/radius、海、棕榈、屋、岩、灯塔 | 原半径算法是假设近似星形海岛；非星形赛道、桥／隧道不可只换控制点；需新地形和空间最近点结构 |
| 换植被 | track.js造型及Batch | 保持道路净空和合批；有风shader只改变植物顶端，不扭路面；改seed会移动装饰且须重验弯道视野 |
| 换动物／车辆 | racers.js 的CHARACTERS/createCat/createKart；ui.js CAST/portrait独立表 | 六猫3D表和UI头像不是一个数据源；更名、头像、选中、颜色、碰撞尺寸与动画都同步 |
| 新圈数／对手数 | simulation.js与UI静态文案，main.js对手布局 | 检查点24不是圈数；动态HUD、结果、地图、胜负都一致；相应新测试明确变更，不全删原断言 |
| 新道具／玩法 | simulation事件与持久状态；effects/audio/ui消费 | 冷却、暂停、碰撞、重开、AI预计时间；先做一个可完成的玩法增量 |
| 品牌／语言 | index.html、ui.js、track.js Canvas标牌、main.js toast/导出文件名 | theme.title只在生成时替换部分文本；搜出所有旧品牌并逐项修；不得批量改变量ID破坏引用 |

### 赛道连续性合同

仍用getPointAt弧长，不能用getPoint重参数化导致AI不同速度；u采样可wrap，progress/圈数不可丢圈。所有车体、道具、漂移痕迹、小地图共享采样和单位。新增高差时track.nearest目前仅XZ，需决定立交重合点如何识别，并将位置y、碰撞、重生也升级。仅把视觉桥抬起来不算可驾驶桥。

### 角色合同

`createKart(id)` 返回THREE.Group；原点在轮胎接地处、前向+Z；userData.animate使用秒和m/s，不改root世界位姿。重建狐狸/兔子时先保留原整体体积，在耳、尾、吻部、配色做差异，再改底盘；不需要外部模型生成服务。共享geometry/material不能在单车dispose中销毁。

## 两个完整创作请求示例

- 「樱花山谷猫猫赛车」：sakura启动 → 把棕榈换成程序化分叉樱花树／花瓣簇；海岸替成有明确边界的溪谷和远山；木桥须可行驶并与AI/最近点一致；换樱花地标/标牌/UI；6角色、3圈、漂移保留；验收正面菜单＋急弯＋桥面＋手机＋完赛。不能只交粉色椰树。
- 「月球兔兔拉力」：保留驾驶状态 → 重写地面/月坑/穹顶和道路；createCat改兔耳/短尾/宇航服但保留轮子动画；低重力只在用户要求时实现物理，不能仅写文案；真空声音可作艺术化音效而非科学模拟承诺；全流程回归。

## 衍生验证如何不被旧基准绑死

先运行未改断言的基线回归，定位原功能是否受损。只改配色/种子仍应通过。真换人物数量、路形或玩法时保留原测试作历史证据，另增变体测试，将旧断言逐条映射到新需求并记录为何不适用；不靠换截图／放宽阈值制造通过。新主题不应追求与旧golden像素一致；用它审查质量层级，再为新主题建立自己的受控镜头。
