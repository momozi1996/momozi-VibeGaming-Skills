# 环境、便携性和真实交付

## 最低能力

- 模型上下文可按需读取 Markdown 和源文件；code agent 能读写目录、执行 shell、安装项目依赖。没有文件／执行工具的纯聊天模型只能指导，无法实际生成并验收产物。
- Python 3.9+：`project.py`、恢复与哈希核验只用标准库。Windows 可把 `python3` 换成 `py -3`；wrapper 的 Python 命令可用环境变量 `PYTHON` 指定可执行文件路径（不要包含参数）。
- 推荐现代 Node（本次实测25.8.1、npm11.11.0）；北郡项目的原生 TS 测试需要支持 strip-types 的 Node，例如22.18+／24+。不要为绕开依赖错误直接执行 npm update；先依据错误检查 lockfile 与 Node 支持。
- 浏览器需 WebGL2、硬件加速；首轮 `npm ci` 需要 npm 网络或已有包缓存。**包不包含 node_modules，不承诺完全离线重编译。** 游戏素材全部本地，不需要运行时 CDN/API Key。
- Python 图像差异工具可选依赖 Pillow、NumPy；优先单独虚拟环境安装，不影响游戏构建。其他验证无需这些图像库。

## 路径与启动

`<SKILL>` 是这个 SKILL.md 的实际安装目录，不是原始笔记目录；`<OUTPUT>` 是用户工作区的新项目；`<REPORT>` 是项目和技能之外的新证据目录。带空格的路径加引号。不要写死开发者用户名或本机路径。

`project.py` 从自己的位置寻找全部输入，不依赖当前工作目录。它拒绝非空输出、symlink输出和与技能重叠的输出；无 `--force`，失败保留证据，不删除用户目录。

用 HTTP 启动，不双击 index.html。开发命令显式绑定127.0.0.1和strictPort；端口占用换端口，不结束未知进程。正式发布前检查资源 base 路径：基线使用 `/assets/` 绝对URL，子目录托管须同时修资源路径，不只改 Vite base。

## 失败恢复

1. 缺文件或hash不符：停止恢复，重新复制完整skill；不要重签清单使污染基线“通过”。
2. npm失败：保留输出，检查registry／版本／缓存，不编造构建成功。
3. 浏览器缺失：安装合法本地Chrome／Chromium或配置可执行路径；不可用就只报告单元与构建通过，浏览器项未验证。
4. 重开工作：读输出 `PROGRESS.md` 和 `GENERATION.json`，在同一输出项目修复，不对非空目录重新create。

## 可移植说明

核心只有通用 Markdown、Python和标准前端项目；`agents/openai.yaml` 仅可选UI元信息。Agent支持自动skill时按该工具的目录规则安装整个文件夹；不支持时任务里指定读取本 `SKILL.md`。仅复制入口文件没有模型、字体、源码，因此不叫完整安装。

跨平台文档不等于所有平台实测。图形、字体、声音听感、真手机性能、全屏权限、手柄和长时间稳定性分别报告。自动化帧夹具不用于宣称真实60fps。旧 docs/tests 报告是历史参考。

辅助工具自检：`python3 "<SKILL>/scripts/selftest.py"` 在临时目录验证完整性、exact字节、两套预设、rebuild空实现和拒绝覆盖等17项；不联网、不运行游戏，也不替代浏览器验收。
