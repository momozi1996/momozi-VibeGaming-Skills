# 运行与交付

## 最小环境

Python 3.9+（仅标准库）和支持 ES modules、Canvas 2D、WebAudio 的现代浏览器。无需 Node/npm、外部图片 API 或另外一个 skill。运行前字体和全部美术已打包；首次安装包自身仍需下载/复制。

`python3 /path/to/game/start.py --port 4310` 只监听 127.0.0.1。目录内资源用相对 URL；服务器从脚本位置服务，不依赖当前工作目录。端口冲突换号，Ctrl+C 停止自己的服务。

## 安装后怎样端到端交付

读 SKILL → create 到新项目 → 按用户要求改造 → start.py 启动 → 打开本地地址 → 告诉用户操作方法。只复制 SKILL.md 不算完整安装，必须复制整个文件夹。不支持 skill 的 agent 可直接读取绝对路径 SKILL.md 按步骤执行。

现有项目不要 create 覆盖；先理解其引擎/结构，按本 skill 的机制和工艺增量移植。

## 输入与浏览器

桌面优先；移动设备提供摇杆/动作按钮或直接点选，横屏体验更好。竖屏保留 HUD 和操作栏，但游戏场景会缩小，不等于所有手机都已真机验证。失焦/切后台暂停并释放输入。

音效第一次点击后解锁，静音按钮可关闭；没有背景音乐文件。自动播放限制不是资源缺失。全屏取决于浏览器支持。

农场使用当前主题与项目 URL 路径独立的 localStorage key，记住上次选择的主题；不同域名/端口的存档隔离。清浏览器数据会清存档；不上传账号服务器。选择新花园时有覆盖确认。其他三个游戏不内置跨会话进度存档。

## 可选检查与发布

`python3 SKILL/scripts/game.py verify` 检查包完整性，不是对游戏美感的评分。常规创作实际打开并试用修改的功能即可；用户需要深入检查时再加相应过程。

项目文件本身可部署到静态 HTTP(S) 托管。只分发 index.html/src/style.css/game-config.json/public 即可运行；start.py 是本地服务工具，不是生产后台。未获请求不自动上传或公开发布。

`?dev=1` 仅在 loopback 主机开放 `window.__GAME__` 本地观察接口，普通地址不挂载；它不是线上管理/作弊 API。自动验收报告若使用了快进或内部接口须说明，不能冒充完整真人试玩。

可选开发检查：已装 Node 18+ 时，在输出项目运行 `node --test tests/game.test.mjs`；它不需要安装依赖，也不参与普通游戏启动。
