# 从完整FPS起点创作，而非从白屏开始

## 默认工作法

先用 `game.py create` 拿到完整源工程和成品。根据用户要求，在输出工程记录“保留的玩法 / 要改的美术与机制 / 不做的范围”，跑通现成起点，然后实改。原样复刻无需重新设计；新主题无需默认从空脚手架重写。无论如何都不在skill冻结输入上开发。

## 文件与连带修改

| 创作目标 | 主入口 | 一起检查 |
|---|---|---|
| 港口／雪地／赛博小巷 | `src/world.js`、`main.js` | 雾、色调、太阳、模型轮廓、地标、远景、阴影与合批；只改标题不是新场景 |
| 改路线／目标点 | `src/map.js` + `world.js` | BLOCKS、BOUNDS、SPAWN、SITE、BOT_SPAWNS、A*、雷达比例、出生方向和可拆距离同步 |
| 换枪外形 | `src/models.js` | weaponScene独立相机、枪口引用、左右手、开镜、换弹与近裁剪，别把武器挡满屏幕 |
| 新枪械数值 | `simulation.js` WEAPONS + `main.js` + `index.html` | 单发/连发门控、弹药守恒、商店价格、slot切换、音效、HUD |
| 改AI／难度 | `simulation.js` | 视线遮挡、重寻路频率、碰撞、出生、开火概率；现有AI不是逐发物理弹道 |
| 换胜负目标 | `simulation.js` + `main.js` | 唯一phase状态源、UI提示、回合/比赛结算、重开与相关测试合同 |
| 换HUD语言／布局 | `index.html`、`style.css`、`main.js` | 文案别截断；保留输入穿透、按钮可点、pointerlock恢复、低高度视口适配 |

## 三种可落地的改造方向（不是预制成品）

- **冬日仓库拆弹**：保留回合机制；增加雪堆/屋檐/货架几何，冷色天空与暖色入口，地面与墙体纹理改成仓库材料。先维持原碰撞路线再迭代新路线，不以一层白色滤镜冒充雪地。
- **霓虹小巷救援**：替换拱门为高架连廊与店面，添加发光招牌和色彩受控的灯光；救援进度需独立实现目标逻辑、胜负文字和交互，不能只是把炸弹改名。
- **靶场计分挑战**：增加真正的计分/靶刷新/限时结果，重新定义哪些伤害与经济系统保留；明确这是改造版而非原始拆弹版本。

## 美术实现经验

- 先用建筑轮廓、近景武器、日照方向和三层远近关系形成辨识度，再补窗沿、电线、沙袋等细节。阴影和雾不能把敌人与目标融进背景。
- `world.js` 按材质合并几何；混合indexed/non-indexed前统一并补UV，避免白屏。不要为每个木板引入一个draw call。
- 枪械和角色是分组刚性几何动画；导出GLB不是现成骨骼动画库，直接换GLB要补关节引用与动画接口。
- WebAudio与鼠标锁定依赖真实用户点击，菜单不能变成自动跳入后台战斗。失焦要清输入和暂停。
- 修改后 `npm run build`，再用输出 `start-demo.py` 看生产成品；否则看到的是旧dist。部署子路径需单独适配base，不属于默认exact。

完成时给出实际图、操作和新增/保留范围。新主题不套原图的像素相等要求；如果新玩法有意改变原测试合同，只改输出项目并说明差异，不能改包内基准或跳断言假装exact。
