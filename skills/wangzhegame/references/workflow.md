# 分步复现流程

## 阶段0：建立可核验计划

1. 确认拿到完整skill，不是单个SKILL.md。读version-contract，运行verify，确认189文件全匹配。
2. 建新输出路径，明确exact还是rebuild。用户未明确重写源码时用exact；明确“由自己的模型写”则参考重写提示词。
3. 写本轮 `PLAN-REPRODUCTION.md` 与 `PROGRESS-REBUILD.md`（这些是新记录，不覆盖原PLAN/PROGRESS）。列本次继承/新增/不做和待测项。
4. 查基线菜单、出生/移动、商店和暂停截图；记 viewport1600×1000。不要靠想象写另一张地图。

## 路线A：exact

1. `reproduce.py restore --out 新目录`：先验证输入再复制，结束自动验证189文件。
2. **可选**构建前 `compare --all` 确認连dist与历史证据都相同。
3. 新目录npm ci，运行check.py --suite all（会做npm test/build）。
4. compare默认只核对reproduction组，重建后的dist字节变化独立说明，不能容忍src/assets被擅改。
5. 打开新截图与新页面，交付证据。若测试环境不同导致失败，记录环境和原断言，不把改源码绕过环境的结果称exact。

## 路线B：rebuild，六模块的完成门槛

使用 `restore --mode rebuild`。脚手架仍附原历史文档以供参考，但**不含原src、dist或artifacts**。继承README提到的功能不是新实现已经完成的证据。

| 阶段 | 要写的东西 | 必须实际看到 / 测到 |
|---|---|---|
| 1 配置与几何 | config导出、五英雄/九装备/16障碍、三路和世界尺度、距离/插值/可行走 | 与game-contract一致；导航路径点有效，不穿对角墙 |
| 2 状态与移动 | Match构造/实体ID/玩家、steer/command/stop、30Hz兼容step | 标准1级500金、训练6级1500；10英雄22塔6水晶2枢纽8营地；轴向/斜向340速度、松键停止 |
| 3 完整战斗 | 普攻/弹道/护甲/伤害/贡献者、20技能、召唤师、出兵/AI/塔保护/经济/复活 | rules.test.js所有原断言；死亡不重复奖励，枢纽保护与自然结束 |
| 4 世界可视化 | 纹理加载、地形/河流/树林/废墟/基地、程序角色与动作、建筑/兵/怪、特效 | 从同一实体状态渲染，真正3D世界；队伍颜色和五角色可辨；几何/灯光对照参考 |
| 5 原生UI | loadImages/GameUI，各屏幕绘制、tooltip/hits/小地图/血条 | 一个可见canvas，0HTML按钮/面板，hit实际可点，画布缩放正确 |
| 6 输入与主循环 | GameControls、renderer/camera/audio/加载门禁、fixed step、DEV API | 实际出生点WASD/箭头动；1–4不冲突；点击/右键长按/按钮/暂停/失焦通过 |
| 7 集成 / 回归 | unit/build/dev/prod/fault/soak/natural、截图差异修正 | 新报告、真实操作、自然闭环与逐画面核对；不得删断言 |

建议先复现导出名/字段/API，再自由组织函数内部。基线测试会读Match字段和UI hit，所以改接口是额外兼容成本。`references/architecture.md` 的调用链是最小兼容面，完整代码在reference-project/src供核对。

## 阶段性止损与续跑

- 先做最小可玩的单英雄切片，再补齐五英雄/全地图/全UI，**切片不能当最终完成**。
- 每阶段写通过/失败项、命令与时间、截图路径、改动文件、下一步。长任务新会话先读这些记录，不重头创建覆盖。
- 如果资源/环境不齐，输出具体缺失与能验证到哪；有进展就继续能做部分，不虚构验收。
- 不替换游戏为赛车/冒险模板，不引入第二个引擎，不新增后端、HTML HUD、在线账号等未请求范围。
- 任何重写残余差异列入新 `REPRODUCTION-DIFF.md`。明确文字/布局、模型、灯光、行为各项，不用“基本像”掩盖未完成。

## 最终交付门禁

exact：输入verify、输出compare、构建和新测试通过，画面人工核对。
rebuild：素材/依赖锁保留、原测试语义不变且通过、核心机制一致、画面差异已核对并如实列出。
两者都须能选择英雄 → 开局 → 操作/战斗/购买 → 死亡复活 → 终局 → 重开；旧截图和静态菜单不能代替。
