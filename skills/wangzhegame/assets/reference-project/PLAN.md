# Rift Forge — 实施计划与验收合同

## 用户要求
5 个英雄起步；以 LOL 为目标，不能廉价化；先计划，真实尺寸/机制，UI 必须引擎内渲染而非 HTML 叠层。

## 技术选择与边界
- 新建 Three.js WebGL 桌面浏览器工程。MOBA 不使用赛车/第三人称模板，仅沿用 allgame 的架构与验收方法。
- 单个 WebGL canvas；世界用透视相机，所有界面用正交 UI scene / CanvasTexture / Sprite 渲染；无 HTML HUD、按钮、菜单。
- 全部模拟量以游戏单位、秒表示。渲染转换为 100 game units = 1 scene unit；移动、技能、AI、地图只消费这一坐标真值。
- 15000 × 15000 游戏单位为本项目地图域，是重建约定，不声称来自官方完整地图网格。三路/河道/基地拓扑重建，不声称官方碰撞一比一。
- 固定 Data Dragon 版本和下载来源。可证实的基础英雄属性读取该版本；技能/战斗是明确记录的功能子集，不宣称等价服务器。
- 美术用程序化真实 3D 重建；如使用 Riot 头像/图标，保留来源和第三方权利标注。不是官方产品，不宣称同等画质或允许商用。

## 实施顺序
1. 数据：版本、5 英雄属性/技能图标、资产来源清单。
2. 模拟：纯 JS 规则，移动、普攻、伤害护甲、兵线、塔、技能、经济、装备、死亡复活、基地胜负。
3. 世界：有体积的地形/道路/河道/野区、植被岩石、双方基地；5 种可辨识角色造型与程序动作。
4. 引擎界面：选人→开始；战斗 HUD、实体血条、技能冷却、小地图、商店、暂停、胜负→重开。
5. 回归：规则单测、真实输入浏览器测试、生产构建运行、截图观察并修改。

## 验收
- 五位英雄均可选，不同 QWER 动作/效果；玩家 + 9 AI；双方三路定时出兵。
- 移动/射程/伤害/冷却由真实状态计算；购买扣金并改变属性，基地附近购买与回城。
- 双方建筑、兵线和基地状态可推进；胜利失败和重开可用。
- 暂停不推进游戏时间，失焦释放输入；右键走位/攻击；QWER/DF/B/P/Y/Space。
- 页面只有游戏 canvas，没有 DOM UI；可见文本、图标、命中区都位于渲染层。
- 留存规则来源与差异清单；不得把截图、build 或测试夹具说成完整 LOL 验证。

## 不在本轮承诺内
原版地图二进制/精确碰撞；官方高精度模型/动画/皮肤；完整英雄服务端脚本；账号匹配/联网/排位/反作弊；全部装备、符文和地图机制；移动端；与官方同等画质。

## 操作修复迭代
默认 WASD/方向键直接移动，1–4 技能、F/G 召唤师技能；C 切经典 QWER/D/F，箭头仍移动。左/右键均走位。全套操作提示必须同步切换；新增逐键、逐按钮、输入释放与生产画面移动验证。
