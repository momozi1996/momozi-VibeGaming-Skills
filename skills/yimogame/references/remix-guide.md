# 从完整原野创作新游戏

默认恢复 exact 后再改 OUT。这里是可操作的创作路线，不是已经实现的多套主题开关。

## 保住画面质感的关键

先看 golden 和 `art-and-scene.md`，再选用户要求改变的部分。画面来自构图、形体、植被密度与动态细节共同作用，不能只替换背景色。

- 镜头：`main.js` 的52°视角、肩偏和相机高度构成第三人称纵深；人物应位于下方偏左，不变成俯视沙盘。
- 空间层次：近景花草和主角，中景小径/河流/风门，远景雾山和城；新场景也要有清楚的路径和可辨地标。
- 角色：`actors.js` 保留清晰轮廓、脸部和装备细节、静态合批与可动pivot；`makeExplorer/makePet` 的root/update接口不变。不要把四肢全部合并导致动画消失。
- 植被/水：`world.js` 的实例草、花、叶片纹理、风shader、水波和粒子是实际渲染，不需要联网下载贴图。
- 色光：天空、雾、半球光、太阳、地表顶点色、角色辅色与UI一起协调；先保留ACES/sRGB和阴影，再调整曝光，不用过曝掩盖粗糙形体。
- 性能：保留 InstancedMesh、共享材质、bake 和高低画质分支。新增景物也纳入合批；草基线最多16万实例，低档减半，不承诺所有设备高帧率。

## 文件与联动改造

| 目标 | 主要文件 | 容易遗漏的联动 |
|---|---|---|
| 新主角/四种新萌宠 | actors.js、state.js SPECIES、ui.js | 各形态动画、scale、生成头像、名称属性和能力必须对应 |
| 海岛/森林/秋日山谷地形 | terrain.js、world.js | 玩家、野生实例、地图都用同一heightAt/riverX；移动路径不能被水/岩石封死 |
| 门改为灯塔/神树等任务点 | state.js PORTAL、world.js、ui.js | 模型坐标、碰撞、世界标记、地图标记和提交距离同时更新 |
| 新捕捉区域 | state.js WILD、world.js | 8个实例的ID/坐标与可达性；任务数按distinct species，不按捕捉次数 |
| 新能力 | main.js 移动/跳跃、state.js、ui.js | 不只改说明；真实速度/水减速/跳跃次数与控制反馈一致 |
| 新标题/图标/HUD | index.html、ui.js、style.css、public/favicon.svg | 中文文案、图鉴、模态和390px触屏布局一起检查 |
| 新存档规则 | state.js SAVE_KEY/serialize/restore | 全新独立作品使用新key；现有作品续作改schema须迁移，不能静默删玩家存档 |

## 示例：月光海岛萌宠

1. 用完整工程先跑通出生→移动→首次捕捉→联结。
2. 定义月蓝/暖灯/奶白主辅色；让主角背包与伙伴有可辨亮色，不让夜色吞掉轮廓。
3. 在terrain统一改岛地与浅水，world改为岛岸、树林、灯塔和远景；保留可走小径，重新安排WILD和PORTAL。
4. 真正改造主角装备与宠物轮廓，例如帆布帽、贝壳背包、水獭与萤火精灵；更新动态头像与伙伴说明。
5. 保留三种收集→灯塔提交→一次奖励→继续探索与读档；如需求不含战斗，不偷偷加空生命系统。
6. `npm run build` 后启动新dist，用真实输入验一次循环，检查初始、联结、图鉴和移动端画面。原golden只帮助比较质感与完整性，不拿不同主题做像素通过判据。

已有自动化基于原角色名、坐标和任务规则；新主题改变这些合同时，应在输出项目中把断言改成新合同并记录原因，不能删除行为验证来伪装通过。不修改安装包内的原测试。

## 完成标准

输出不是「后续可以实现」清单：要求中的新形体/场景实际进入游戏，输入和状态驱动UI，能完成任务并保存，最终构建包含这些修改。交付可玩的地址、截图和已知边界。未完成部分明确列出，不称任意创意都已一键生成。
