# 同类格斗创作：从完整游戏出发

这些是供Agent实际实施的改造方法，不是包内已经完成的可切换主题。用户只要复刻时不要改造。

## 先保住玩法，再改变观感

恢复完整工程并试一次选人→训练→攻击。只修改OUT，保留Match为状态真值、60Hz固定tick和既有完整流程。

| 创作内容 | 文件 | 联动要求 |
|---|---|---|
| 换雨夜为黄昏港口/地铁站 | public/assets/stage、Renderer.ts | 背景分层、地面GROUND=455、站位/阴影/道具比例一致；渲染层次和清晰度不能退化 |
| 街机标题/配色/HUD | UI.ts、styles.css、index.html | 仍是全窗口游戏，不改成宣传站；选人、战斗、结果和触屏一起设计 |
| 换角色/服装 | 新素材图集、JSON、头像、definitions、Animator | 真正替换形体和动作，不只改名字；逐帧rect/bounds/sourceRoot一致，保持固定脚底根锚点 |
| 改招式 | definitions、FighterFSM、Match、combat-data对照 | 启动/有效/恢复、hitstop、判定框、取消窗口、音画反馈同时更新 |
| 调CPU/模式 | CPU、Match、main、UI | 仍能完整开始、结束、再战；新增功能不能只挂按钮 |

## 美术不能缩水

- 默认直接使用随包原生精灵；不要把整张图集统一缩小再放大，不要把裁剪bbox中心当锚点。
- 人物约184逻辑像素高、菜单1.25倍；960×540逻辑舞台按16:9适配并匹配DPR，不加整屏模糊/扫描线掩盖细节。
- 新角色必须补齐idle/walk/jump/fall/crouch/guard/hurt/down/win及各普通/必杀动画；原生裁边图集不是等宽帧栅格。
- 新场景至少有远景、中景、地面层，留出两位格斗者可读的轮廓空间；让角色不被菜单遮罩压暗。
- 保留白闪、火花、格挡弧、落地尘、轻重震屏与音效反馈，逻辑hitstop不取决于显示帧率。
- 默认包不需要生图服务。用户要求全新资产而本地没有时，如实实施程序绘制或使用用户提供的授权素材；不要悄悄联网搜商业KOF拆包。

## 数值和素材改造顺序

先背景/UI，再角色图集，最后战斗数值；每步保留可玩成品。新角色如复用动作机制，保留关键clip名并生成自己的帧元数据；修改招式时不要破坏同帧先收集后结算、一次招式一次命中、hitstop输入缓冲及朝向相对指令。

重导素材的可选依赖为Pillow/requests，默认成品已带处理完的PNG/JSON，无需重导。缺少工具时明确限制，不删除完整素材以简化任务。

## 最后重新构建

`npm run build` 后才是新dist；直接启动旧dist不代表修改已进入游戏。验证选人、人机攻击、双人控制、训练、命中取消、回合结果/再战和触屏。新角色或招式改变了原测试合同，更新OUT内相应断言并说明，不删除验证以伪装通过。不拿新主题与原主题做强制像素一致。

如果要新增联网、投技、手柄、同角色对战等，明确为新增开发，不说基线已经实现。
