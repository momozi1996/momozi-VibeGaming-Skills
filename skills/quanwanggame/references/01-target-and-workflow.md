# 01｜目标、权威顺序与复现路线

## 唯一目标

复现 **NEON IMPACT · 霓虹对决**：2026-09-18 完成的「native-sprites-arcade-ui-v2」。这是一款 PixiJS / TypeScript 的两角色原创街机格斗 Demo，目标不是商业 KOF 游戏的完整复制。

冻结版本特征：
- AVA 长棕发、绯红上衣、深灰下装、短靴；REN 红发、深色背心、黄褐长裤、蓝色腰带/脚踝装饰。
- 窗口直接进入全屏式街机选人，不出现网站导航、介绍卡片或页脚。
- 背景是雨夜街道，菜单左右动态人物，中间 VS、小头像、模式和开始按钮；战斗用金色血条。
- 逻辑分辨率 960×540，人物身体约 184 逻辑像素高，菜单放大 1.25 倍。

## 权威顺序

遇到文档、猜测或截图片段冲突时：
1. `assets/reference-project/src/`、运行时素材 JSON、锁文件、`project-manifest.json`：精确实现与文件基线。
2. `assets/baseline/deterministic/`：固定时刻参考画面；`refresh-*.png`：最新动态实测画面。
3. 原始 tests、browser-test、refresh-test 的断言：已实现行为与边界。
4. references 的参数、玩法、架构文档。
5. 通用格斗常识与模型自带模板：不能覆盖既有项目行为。

原始 source-cache 中保留了旧 `ava-lee.gif` 作为历史原件，**不是 v2 角色输入**。探索阶段的联系表/错误帧号截图没有作为新包的验收基准。不能凭旧资产文件名决定使用哪个版本。

## 路线 A：保真恢复（默认）

直接把 reference-project 的文件恢复到新目录。保留 package-lock、public/assets、原始素材和测试。离线安装、构建、回归、截图对比。

- 优点：源码/参数/素材可精确一致，模型不需要凭空重写所有细节。
- 必须做：verify + 测试 + 打开副本。不能只是复制完就宣布所有环境都能运行。
- 不该做：升级库、迁移 React、改变 CSS 排版、替换角色、把原生图集做 AI 补绘、合并全部模块。

## 路线 B：独立实现（仅明确要求时）

允许模型重新编写实现，但仍复用原生素材、锁文件和测试规格；不把“重写”误解成重新设计。原有 API / DOM selector 是兼容接口，应保留或提供适配层。

- 建议顺序：类型/时钟 → 输入 → FSM/判定 → Match → 动画/渲染 → UI/声音 → 验证。
- 玩法和图集元数据必须精确；颜色、位置、字体不能随意发挥。
- 完全不阅读源码而仅凭本包文案生成，风险明显更高。95% 是需验证的目标，不是保证。

## 交付边界

只在目标目录修改；不影响原游戏、原服务、全局 npm 配置或任何用户其它项目。启动器使用空闲端口，测试脚本启动自己的生产服务。无需云部署、账户、登录、API Key、授权弹窗或额外外站素材搜索。
